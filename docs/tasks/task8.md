- PRD FR-14, FR-17~FR-20 (자폭, 라운드 클리어, 게임 오버 전환)

- `CLAUDE.md` Assets: 포즈 사용 규칙(`critical_*`는 특수 조건, `fail`은 1,1,1)

## 선행 task

- Task 4 (포즈 보정)
- Task 6 (게임 화면, 로그 창)
- Task 7 (주사위 연출)

## 구현 기능 목록
- 턴 흐름 컨트롤러: 행동 선택 → 주사위 굴림 연출 → 결과 연출 → 로그 → 다음 턴을 순서대로 진행한다. Task 6의 임시 연결을 이 흐름으로 교체한다. 배틀 로직이 내보내는 이벤트를 연출 단계로 바꾼다.
- 포즈 전환: 행동하는 캐릭터는 `attack`/`heal`, 특수 조건이면 `critical_attack`/`critical_heal`, 마법사 1,1,1은 `fail`, 피해를 입은 캐릭터는 `hit`, 연출이 끝나면 `idle`로 돌아간다.
- 특수 조건 문구: `critical`이면 "Critical!"과 발동한 효과 설명(규칙 엔진의 설명 문구, 계산식 없이 효과만)을 주사위 영역 안, 주사위 아래에 띄운다. 로그에는 효과 설명을 남기지 않고 총 데미지/회복량만 남긴다. 마법사 1,1,1은 "FAIL!"을 띄우고 "Critical!"은 띄우지 않는다. 일반 합산/최고 눈금 결과에는 띄우지 않는다.
- 로그 메시지: "유저가 상대에게 ~ 데미지를 주었다!", "상대가 유저에게 ~ 데미지를 주었다!", 회복, 자폭, 라운드 클리어 회복 메시지를 한국어로 추가한다.
- AI 턴: AI가 선택한 행동(공격/회복)을 화면에 표시하고, 주사위를 자동으로 던져 결과를 처리한다. 턴과 턴 사이에 결과를 읽을 수 있는 짧은 지연을 둔다.
- 입력 잠금: 주사위 굴림, 결과 연출, AI 턴이 진행되는 동안 공격/회복 버튼과 주사위 입력을 비활성화한다(Pause 버튼은 제외). HP가 0이 된 뒤에는 입력을 받지 않는다.
- 종료 전환: 적 HP 0이면 라운드 클리어 연출(회복량 표시)과 함께 다음 ROUND로, 플레이어 HP 0이면 GAME OVER 화면으로 넘어간다.
- 모든 연출 타이머는 게임 루프의 dt 기반으로 구현한다. (일시정지 지원)

## 검증 기록
로컬 Chrome(헤드리스)으로 실제 클릭과 던지기를 시험했다. 시나리오별 시드는 임시 테스트로 찾았다.
- 전사 같은 눈금(시드 2, 당시 x 3 규칙): 굴림이 끝나면 `critical_attack` 포즈와 "Critical!" + "같은 눈금! (2+2) x 3 = 12"가 뜨고, 그 다음에 상대 HP 바와 로그가 바뀌며 상대가 `hit`, 이어서 모두 `idle`로 돌아왔다.
- 일반 결과(전사 시드 1): 문구 없음, `attack` 포즈, 상대 `hit`.
- 도적 추가 굴림(시드 2), 마법사 모두 홀짝(시드 3) / 연속(시드 20) / 6,6,6(시드 341): 모두 "Critical!"과 `critical_attack`. 회복 critical(전사, 마법사 시드 2)은 `critical_heal`, 일반 회복(시드 1)은 `heal`에 문구 없음.
- 마법사 1,1,1(시드 507): "FAIL!"만 뜨고 `fail` 포즈, "Critical!"은 한 번도 뜨지 않았다. HP 0, 이어서 GAME OVER 화면.
- AI 마법사 자폭(전사 시드 1007): "공격!" 말풍선과 로그, 주사위가 자동으로 굴러감, 상대 `fail` + "FAIL!", "ROUND 1 CLEAR!", ROUND 2 시작(새 적 도적), 다시 내 차례.
- 입력 잠금: 던진 뒤 내 결과 연출과 AI 턴이 끝날 때까지 공격/회복 버튼과 주사위 영역을 400번 눌렀지만 배틀에 전달된 행동은 플레이어 1회, AI 1회뿐이었다.
- 일시정지: `loop.paused`로 멈추면 포즈, 배너 시간, HP, 로그가 1.5초 동안 그대로였고 풀면 이어졌다.
- 마법사 두 판(시드 21, 5)을 실제 던지기로 GAME OVER까지 진행했다. 콘솔 오류는 없었다.
