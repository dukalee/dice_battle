# PRD: Dice Battle (주사위 배틀)

> 초안. 게임 규칙의 원본은 `docs/Spec.md`이며, 이 문서는 Spec을 요구사항 ID와 수용 기준으로 정리한 것이다. 규칙이 충돌하면 Spec.md를 따른다.

## 1. 배경

- 현재 문제: 주사위 기반 턴제 배틀 게임을 처음부터 새로 만드는 프로젝트이며, 기존 구현은 없다.
- 관련 문서: `docs/Spec.md` (게임 규칙의 원본), `CLAUDE.md` (프로젝트 규칙)

## 2. 대상 사용자

- 주요 사용자: 게임을 즐기는 일반 유저
- 보조 사용자: 없음

## 3. 범위

이번 작업에 포함:

- [ ] 캐릭터 3종(전사, 도적, 마법사)과 캐릭터별 공격/회복 규칙
- [ ] 주사위 굴림(누르고 떼는 입력, 굴러가는 연출, 눈금 표시)
- [ ] 플레이어 vs AI 턴제 배틀, ROUND 진행, 라운드 클리어 시 회복
- [ ] 초기 / 설명서 / 캐릭터 선택 / 게임 / GAME OVER 화면, Pause 메뉴
- [ ] 캐릭터 PNG 스프라이트 (캐릭터당 6종, 마법사는 `fail` 포함 7종), 포즈별 보정 설정(크기 배율, 몸통 기준점), WebP 변환
- [ ] 16:9 화면 (논리 해상도 1280x720, 창 크기에 맞춰 스케일링)
- [ ] 전투 로그 창과 Critical!/FAIL! 문구

이번 작업에 포함하지 않음:

- [ ] 효과음, BGM
- [ ] 최고 라운드 기록 저장
- [ ] 서버, 계정, 멀티플레이
- [ ] 라운드에 따른 적 강화

## 4. 사용자 흐름

1. 사용자가 초기 화면에서 게임 시작 버튼을 누른다. (설명서 버튼으로 규칙을 먼저 볼 수 있다.)
2. 사용자가 캐릭터 선택 화면에서 전사, 도적, 마법사 중 하나를 선택한다.
3. 시스템은 ROUND 1을 시작하고, 3종 중 하나를 랜덤으로 적으로 정한다. 두 캐릭터의 HP는 최대치이다.
4. 플레이어의 턴으로 시작한다. 사용자가 공격 또는 회복 버튼을 선택한다.
5. 사용자가 주사위 영역을 꾹 눌렀다 떼면 주사위가 굴러가고, 눈금에 따라 시스템이 효과를 적용한다.
6. 시스템은 결과를 로그로 출력하고, 특수 조건이 발동했으면 Critical! 문구(자폭은 FAIL!)를 보여준다.
7. AI가 랜덤으로 공격 또는 회복을 선택하고, 주사위를 자동으로 던져 효과를 적용한다.
8. 한쪽의 HP가 0이 될 때까지 4~7을 반복한다.
9. 플레이어가 살아남으면 최대 HP의 절반(내림)만큼 회복하고 다음 ROUND로 진입한다.
10. 플레이어의 HP가 0이 되면 GAME OVER 화면에 도달 라운드가 표시되고, 재시작 또는 타이틀 이동을 선택한다.
11. 게임 중 Pause 버튼을 누르면 게임이 멈추고 이어하기, 재시작, 타이틀 이동을 선택할 수 있다.

## 5. 기능 요구사항

캐릭터 공통
- FR-1: 캐릭터는 공격 또는 회복 중 하나를 선택해 턴을 진행한다. 공격은 상대에게 데미지를 주고, 회복은 자신의 HP를 회복한다.
- FR-2: 행동을 정하면 주사위를 굴리고, 캐릭터의 특성에 따라 눈금별로 데미지 또는 회복량이 결정된다.
- FR-3: HP는 항상 0 이상, 최대 HP 이하이다. 최대 HP에서도 회복을 선택할 수 있으며 이 경우 턴만 소모된다.
- FR-4: 주사위 개수는 캐릭터별 고정값이며 게임 중 변하지 않는다.
- FR-5: 주사위 눈금은 1~6의 균등 난수이다. 결과를 먼저 정하고 애니메이션은 그 값으로 멈춘다.
- FR-6: 난수 생성기는 테스트를 위해 주입(시드 지정)할 수 있어야 한다.

전사 (최대 HP 100, 주사위 2개)
- FR-7: 공격 시 두 주사위가 같은 눈금이면 (합) x 4 데미지, 아니면 합만큼 데미지를 준다.
- FR-8: 회복 시 두 주사위가 같은 눈금이면 50, 아니면 합만큼 회복한다.

도적 (최대 HP 70, 주사위 2개)
- FR-9: 공격 시 두 주사위가 모두 짝수 또는 모두 홀수이면 주사위 2개를 더 굴려 4개의 눈으로 판정한다. 4개가 모두 같으면 75 데미지(일격필살), 같은 눈 3개(트리플)이면 30 데미지, 같은 눈 2개씩 두 쌍이면 50 데미지, 그 외에는 4개의 합만큼 데미지를 준다. 판정은 눈의 개수로만 하며 어느 주사위에 나왔는지는 상관없다. 추가 굴림은 자동으로 진행되며 플레이어의 추가 입력은 없고, 최대 1회이다.
- FR-10: 공격 시 두 주사위가 모두 짝수/홀수가 아니면 처음 굴린 두 주사위 중 더 큰 눈금만큼 데미지를 준다. (추가 굴림 없음)
- FR-11: 회복 시 두 주사위가 모두 짝수 또는 모두 홀수이면 주사위 1개를 더 굴린다. 3개가 모두 짝수 또는 모두 홀수이면 20, 아니면 3개의 합만큼 회복한다. 두 주사위가 모두 짝수/홀수가 아니면 두 주사위의 합만큼 회복한다.
- FR-11a: 추가 굴림은 처음 주사위가 멈춘 뒤 약 1.3초의 긴장 구간(처음 주사위 강조, "홀짝이 같다! 한 번 더!" 문구, 주사위가 물러나며 "?" 빈 자리 표시: 공격 두 개, 회복 한 개)을 거친 다음 던진다. 처음 주사위는 일반 배치로 멈추어 추가 굴림을 미리 알 수 없다.

마법사 (최대 HP 50, 주사위 3개)
- FR-12: 공격은 다음 우선순위로 먼저 만족하는 조건 하나만 적용한다. 6,6,6은 100 데미지(모든 캐릭터를 한 방에), 1,1,1은 자신의 HP를 0으로(즉사), 2,2,2/4,4,4는 자신이 25 데미지(FAIL!), 3,3,3/5,5,5는 25 데미지, 그 외 모두 홀수 또는 모두 짝수는 (합) x 2, 연속된 3개(순서 무관)는 45, 그 외는 가장 높은 눈금만큼 데미지를 준다.
- FR-13: 회복은 다음 우선순위로 하나만 적용한다. 세 주사위가 모두 같으면 최대 HP까지 전부, 모두 홀수 또는 모두 짝수이면 30, 그 외는 합만큼 회복한다.
- FR-14: 마법사가 1,1,1로 공격하면 자신의 HP가 0이 되어 즉시 패배한다. AI 마법사가 굴리면 플레이어가 해당 라운드를 클리어한다.

게임 진행
- FR-15: 플레이어는 게임 시작 시 세 캐릭터 중 하나를 선택하고, 선택이 끝나면 ROUND 1이 시작된다.
- FR-16: 매 ROUND마다 적 캐릭터를 3종 중 균등 확률로 랜덤 선정한다. 플레이어와 같은 종류가 나올 수 있다.
- FR-17: 적의 HP는 매 라운드 최대 HP로 시작하며 라운드가 올라가도 강화되지 않는다.
- FR-18: 턴제이며 항상 플레이어의 턴으로 시작한다. AI는 공격 또는 회복을 랜덤으로 선택한다.
- FR-19: 플레이어가 살아남으면 `최대 HP / 2`(소수점 내림)만큼 회복하고(최대 HP 초과 불가) 다음 ROUND로 진입한다.
- FR-20: 플레이어의 HP가 0이 되면 GAME OVER 화면으로 이동한다. 승리 조건은 없으며 패배할 때까지 라운드가 계속된다.

화면
- FR-21: 16:9 비율, 논리 해상도 1280x720이며 창 크기에 맞춰 비율을 유지한 채 스케일링한다.
- FR-22: 초기 화면에는 "Dice Battle" 타이틀, 게임 시작 버튼, 설명서 버튼이 있고, 배경에서 전사, 마법사, 도적이 critical_attack 포즈로 삼각 구도를 이루며 대치한다(마법사 가운데 뒤, 전사와 도적 앞 양옆). 설명서는 게임 규칙과 3종 캐릭터 규칙을 스크롤 없이 한 화면에 요약해 보여주고 초기 화면으로 돌아올 수 있다.
- FR-23: 캐릭터 선택 화면은 캐릭터별 색을 가진 세로 카드 3장으로 구성한다. 각 카드에는 이름, 일러스트, 스탯(최대 HP 게이지, 주사위 개수), 한 줄 소개, 공격/회복 규칙 줄 4~5개가 있다. 별도의 "선택" 버튼은 없고 카드 전체가 선택 버튼이며("카드를 눌러 선택" 안내 표시), 마우스를 올리면 카드가 떠오른다. 전체 규칙은 설명서에서 본다.
- FR-24: 게임 화면은 좌측에 플레이어, 우측에 AI 캐릭터를 두고, 최상단 좌우에 각각 HP 바를 표시한다. 현재 ROUND 번호도 표시한다.
- FR-25: 하단에 공격/회복 버튼이 있고, 행동이 정해지면 주사위 영역을 꾹 눌렀다 떼는 동작으로 던진다. 누르는 동안 주사위가 흔들리고, 떼면 굴러가며 눈금이 보인다. 누른 시간이 짧아도 떼면 던지며, 이 경우 약한 연출로 굴러간다.
- FR-26: 누른 시간은 연출(흔들림, 굴러가는 세기)에만 영향을 주며 눈금에는 영향을 주지 않는다.
- FR-27: 캐릭터 표의 특수 조건(일반 합산/최고 눈금이 아닌 규칙)이 발동하면 "Critical!" 문구와 발동한 효과 설명을 출력한다. 계산식은 보여주지 않고 효과만 말로 설명하며, 이 설명은 로그가 아니라 주사위 화면(주사위 영역 안)에 출력한다. 로그에는 총 데미지/회복량만 남긴다. (예: "같은 눈금! 두 눈의 합의 4배 데미지") 마법사 1,1,1 자폭처럼 불리한 특수 조건에는 "Critical!" 대신 "FAIL!"을 출력한다.
- FR-27a: 특수 조건(Critical! 또는 FAIL!)이 나오면 주사위가 멈춘 뒤 먼저 주사위를 하나씩 튀어 오르게 하며 빛내고 효과 설명을 보여 준 다음, 캐릭터가 critical(또는 fail) 포즈로 공격/회복하고 "Critical!"/"FAIL!" 글자를 띄운다. 공격, 회복 모두 같다. 일반 결과에는 이 연출이 없다.
- FR-28: 로그 창에 "유저가 상대에게 ~ 데미지를 주었다!" 같은 행동 결과를 출력한다.
- FR-29: AI 턴에서는 선택한 행동을 표시하고 주사위를 자동으로 던진 뒤 결과를 로그로 출력한다. 턴 사이에는 짧은 지연을 둔다.
- FR-30: 주사위 굴림, 효과 연출, AI 턴이 진행되는 동안 공격/회복 버튼과 주사위 입력을 비활성화한다(Pause 버튼은 제외). HP가 0이 된 뒤에는 입력을 받지 않는다.
- FR-31: 상단 중앙의 Pause 버튼은 주사위 굴림, 연출, AI 턴 중에도 언제든 누를 수 있고 그 자리에서 멈춘다. ESC 키로도 Pause 메뉴를 열고 닫을 수 있다. 이어하기를 누르면 이어서 진행한다. Pause 메뉴에서는 이어하기, 재시작(캐릭터 선택 화면으로), 타이틀 이동을 선택할 수 있다.
- FR-32: GAME OVER 화면에는 도달한 라운드와 재시작(캐릭터 선택 화면으로), 타이틀 이동 버튼이 있다.

## 6. 비기능 요구사항

- 성능: 주사위 최대 4개(도적 추가 굴림 시)의 굴림 애니메이션이 끊김 없이 동작한다. (목표 60fps)
- 접근성: 명시된 요구 없음.
- 보안: 해당 없음. 서버 통신과 사용자 데이터가 없다.
- 로깅/모니터링: 해당 없음. 개발 중 디버깅용 콘솔 로그 정도만 사용한다.
- 호환성: Chrome, Edge, Firefox 최신판. 마우스를 우선으로 하며, 입력은 Pointer Events로 처리하여 터치는 동작만 보장한다. 창 크기가 달라져도 16:9 비율을 유지한다.
- 비주얼: 모든 화면이 같은 스타일(황혼의 판타지 배경, 유리 패널, 광택 버튼, 캐릭터별 색)을 쓴다. 정지된 배경, 패널, 로고는 한 번만 그려 두고 복사해 쓰며(블러 그림자 같은 무거운 효과는 매 프레임 그리지 않는다), 도적 주사위 4개와 크리티컬 이펙트가 겹쳐도 Chrome, Edge, Firefox에서 60fps를 유지한다.
- 언어: UI 문구는 한국어이다. 글꼴은 번들로 포함한 한글 게임 폰트를 쓴다(본문 Jua, 제목/배너 Black Han Sans, 모두 SIL OFL). 사용하는 글자만 뽑은 작은 WOFF2로 만들어 포함하며(`npm run fonts:build`), 외부 서버에서 내려받지 않는다.
- 기술: HTML5 Canvas + TypeScript, Vite로 빌드한다. 단위 테스트는 Vitest를 사용한다.
- 테스트 용이성: 규칙 계산(캐릭터별 눈금 → 효과)은 렌더링과 분리하여 시드를 주입해 검증할 수 있어야 한다.

## 7. 수용 기준

- [ ] Given 전사가 공격할 때, When 주사위가 4, 4이면, Then 32 데미지를 준다.
- [ ] Given 전사가 공격할 때, When 주사위가 3, 5이면, Then 8 데미지를 준다.
- [ ] Given 전사가 회복할 때, When 주사위가 같은 눈금이면, Then 50 회복하되 최대 HP 100을 넘지 않는다.
- [ ] Given 도적이 공격할 때, When 첫 굴림이 4, 2이고 추가 굴림이 3, 5이면, Then 14 데미지를 준다.
- [ ] Given 도적이 공격할 때, When 첫 굴림이 4, 3이면, Then 4 데미지를 주고 추가 굴림은 없다.
- [ ] Given 도적이 공격할 때, When 4개의 눈이 6,6,3,3 또는 4,2,4,2처럼 두 쌍이면, Then 50 데미지를 준다.
- [ ] Given 도적이 공격할 때, When 4개의 눈이 6,6,6,1 또는 2,4,4,4처럼 같은 눈 3개(트리플)이면, Then 30 데미지를 준다.
- [ ] Given 도적이 공격할 때, When 4개의 눈이 6,6,6,6처럼 모두 같으면, Then 75 데미지를 준다. (트리플이나 두 쌍으로 세지 않는다)

## 9. 구현 순서 메모

- 캐릭터 스프라이트는 사용자가 준비해 `assets/characters/`에 넣었다. 전사 6종, 도적 6종, 마법사 7종(`fail` 포함)이 모두 준비되어 있다.
- 구현은 `docs/tasks/task1.md`~`task9.md` 순서로 진행한다. 각 task의 선행 task가 끝난 뒤에 시작한다.
- 파일 이름은 `<character>_<pose>.png` 형식이며, 특수 포즈는 `critical`로 통일한다.
- 포즈별 크기/몸통 기준점 보정 JSON(`src/data/sprites.json`)과 WebP 변환(`npm run assets:build`)은 Task 4에서 만들었다.
