# Task 7: 주사위 굴림 연출과 입력

## 참조
- PRD FR-2, FR-4 (주사위 개수), FR-5 (결과를 먼저 정하고 애니메이션은 그 값으로 멈춤), FR-9 (도적 추가 굴림은 자동)
- PRD FR-25 (꾹 눌렀다 떼면 던짐, 짧아도 던짐), FR-26 (누른 시간은 연출에만 영향)
- PRD 비기능: 성능(주사위 최대 4개 애니메이션 60fps)
- PRD 수용 기준: 누르는 시간이 달라도 같은 시드에서 눈금 불변, 짧은 클릭, 도적 추가 굴림 자동

## 선행 task
- Task 2 (규칙 엔진: 눈금 결과)
- Task 6 (게임 화면)

## 구현 기능 목록
- 주사위 렌더링: 6면 눈금을 캔버스로 그린 주사위 (크기, 회전, 그림자). 눈금이 정확히 보여야 한다.
- 주사위 영역: 행동(공격/회복)을 고른 뒤에 활성화되고, 캐릭터의 주사위 개수(2~3개)를 표시한다.
- 던지기 입력: 주사위 영역을 누르는 동안 주사위가 흔들리고(누른 시간이 길수록 세게), 떼는 순간 던진다. 영역 밖에서 떼도 던져진다. 누른 시간이 짧아도 던지며, 이 경우 약한 연출로 굴러간다.
- 굴림 연출: 결과 눈금은 규칙 엔진에서 먼저 정해지고, 주사위가 굴러가다 정해진 눈금으로 멈춘다. 누른 시간은 흔들림과 굴러가는 세기에만 영향을 준다.
- 도적 추가 굴림 연출: 첫 굴림이 조건을 만족하면 추가 주사위 2개가 플레이어 입력 없이 자동으로 굴러가고, 총 4개의 눈금이 보인다.
- AI 굴림 연출: 플레이어 입력 없이 같은 굴림 연출이 자동으로 실행된다.
- 연출 완료 콜백: 모든 주사위가 멈추면 호출해 Task 8이 결과를 이어서 처리하게 한다.
- 연출 진행은 게임 루프의 dt 기반으로 구현한다. (일시정지 지원)

## 완성 조건
- [x] 행동을 고르기 전에는 주사위 영역이 비활성화이고, 고른 뒤에 활성화된다.
- [x] 눌렀다 떼면 주사위가 굴러가 정해진 눈금으로 멈추고, 눈금이 정확히 읽힌다.
- [x] 누르는 동안 주사위가 흔들리고, 오래 누를수록 연출이 세다.
- [x] 아주 짧게 눌렀다 떼도 약한 연출로 던져진다.
- [x] 같은 시드에서 누른 시간을 바꿔도 멈추는 눈금이 같다. (단위 테스트)
- [x] 주사위 영역 밖에서 마우스를 떼도 던져진다.
- [x] 전사/도적은 주사위 2개, 마법사는 3개가 표시된다.
- [x] 도적 추가 굴림 조건이면 입력 없이 주사위 2개가 더 굴러가 4개가 보인다.
- [x] 주사위 4개와 캐릭터 스프라이트를 함께 그려도 프레임이 끊기지 않는다. (60fps 목표, 확인 방법을 기록)
- [x] `npm run test`와 `npm run build`가 통과한다.

## 검증 기록
- 60fps 확인 방법: 로컬 Chrome(헤드리스)에서 도적(주사위 4개)의 던지기 전체 구간 동안 `requestAnimationFrame` 간격을 측정했다. 148프레임, 평균 16.67ms(60fps), 99퍼센타일 16.9ms, 최대 17.4ms였다. 이때 양쪽 캐릭터 스프라이트와 4개의 주사위를 함께 그리고 있었다. (측정 대상은 이 컴퓨터의 소프트웨어 렌더링이며, 실제 사용자 환경에서는 다를 수 있다.)
- 던지기 연출 길이(시드 21, 같은 눈금 [3, 2]): 탭 845ms, 0.5초 누름 1115ms, 1.4초 누름 1494ms. 세 경우 모두 눈금과 이후 AI 턴 결과가 같았다.
- 주사위가 멈추기 전에는 HP 바와 로그가 결과를 보여주지 않는다. (던진 직후 배틀 상태는 이미 59인데 화면은 75를 유지했다.)
